# Project state

## Decisions

| ID | Decision | Rationale | Status | Date |
| --- | --- | --- | --- | --- |
| AD-001 | The service uses a domain-oriented hexagonal architecture; HTTP, SQS, PostgreSQL, OIDC, observability, and Fx remain outside the domain | the financial model must be independent of frameworks and both ingress paths must share one use case | active | 2026-09-18 |
| AD-002 | Uber Fx is restricted to the composition root and adapter lifecycle, with constructor injection and no service locator | the challenge mandates Fx while the domain must remain framework-independent | active | 2026-09-18 |
| AD-003 | `Money` uses checked `int64` minor units and a currency value; external financial inputs use canonical two-decimal strings | floating point is forbidden and exact persistence, hashing, and overflow detection are required | active | 2026-09-18 |
| AD-004 | Financial writes serialize per wallet with a PostgreSQL row lock and commit state, balance, ledger, inbox, and outbox atomically | correctness must hold across independent processes without global or process-local locks | active | 2026-09-18 |
| AD-005 | The first successful direct `REFUND` or `ROLLBACK` of a `BET` permanently consumes its compensation right; rolling back a refund does not reopen the bet | the user selected a single-use compensation lineage to prevent duplicate credits and reversal cycles | active | 2026-09-18 |
| AD-006 | HTTP and SQS idempotency use the same versioned canonical business projection and SHA-256 digest, backed by provider-scoped database uniqueness | raw transport bytes differ across ingress paths and in-memory deduplication does not survive restart | active | 2026-09-18 |
| AD-007 | Durable SQS inbox and transactional outbox are the only messaging consistency mechanisms; FIFO deduplication is an optimization | at-least-once delivery and crashes around commits must not duplicate money or lose committed events | active | 2026-09-18 |
| AD-008 | Verification uses the `standard` tlc-spec-lean profile | the user selected recomputed coverage and fault injection for the financial and distributed assertion surfaces | active | 2026-09-18 |
| AD-009 | The local OAuth 2.0/OIDC provider is Keycloak with an imported realm and `client_credentials` service accounts | the user confirmed the source's recommendation to provide reproducible external authentication without application-issued tokens | active | 2026-09-18 |
| AD-010 | HTTP authorization uses route-specific scopes and the authenticated `provider_id` claim is authoritative for provider operations | the user confirmed separate wagering, wallet, reconciliation, and metrics permissions without trusting body or path identity | active | 2026-09-18 |
| AD-011 | Providers may query an external transaction by internal ID only when it belongs to their authenticated `provider_id`; internal `OPENING` transactions remain internal-only | the user confirmed a useful lookup route with ownership checks and cross-provider non-disclosure | active | 2026-09-18 |
| AD-012 | PostgreSQL access uses `pgx/v5` with explicit SQL and schema evolution uses separate `golang-migrate` up/down migrations | the user confirmed transparent transaction, lock, constraint, and rollback mechanics without ORM auto-migration | active | 2026-09-18 |
| AD-013 | External wallet and wagering operations support only BRL; USD exists only as a valid domain currency for incompatibility tests | the user confirmed the narrower currency scope to avoid expanding the challenge while preserving currency-aware Money behavior | active | 2026-09-18 |
| AD-014 | Internal wallet, transaction, ledger, inbox-row, outbox-row, and event identifiers use canonical UUIDv7 | the user confirmed decentralized opaque IDs with temporal index locality while preserving external provider identities separately | active | 2026-09-18 |
| AD-015 | External provider identifiers are bounded ASCII contracts and internal player, wallet, and transaction identities are canonical UUIDs; no input normalization is silent | the user confirmed explicit limits that protect indexes, logs, and deterministic idempotency | active | 2026-09-18 |
| AD-016 | Operations without an unresolved reference reach `PROCESSED` or `REJECTED` in their first SQL transaction and never commit an intermediate `PENDING` state | the user confirmed the simpler synchronous durable path while reserving asynchronous continuation for `PENDING_REFERENCE` | active | 2026-09-18 |
| AD-017 | `WIN.referenceExternalTransactionId` is optional, but when supplied it must resolve to a compatible processed `BET`; an absent reference waits durably | the user confirmed the source's optional contract while rejecting unvalidated reference metadata | active | 2026-09-18 |
| AD-018 | A missing transaction reference retries durably for 24 hours with exponential backoff from 1 second to 15 minutes and deterministic jitter up to 10% | the user confirmed a business TTL rather than a separate attempt cap, preserving retry state across restarts | active | 2026-09-18 |
| AD-019 | A dependent transaction keeps waiting while its reference is pending, but rejects immediately with `REFERENCE_NOT_PROCESSED` when the reference reaches `REJECTED` or `FAILED` | the user confirmed that only a processed reference can support dependent financial behavior | active | 2026-09-18 |
| AD-020 | `FAILED` is reserved for already-accepted asynchronous work that cannot continue for a non-transient durable reason; transient PostgreSQL/SQS failures always retry | the user confirmed that infrastructure unavailability must never become an irreversible terminal result | active | 2026-09-18 |
| AD-021 | HTTP transport, contract, and authorization errors use `{"error":{"code","message","correlationId"}}`, while durable business rejections are `200` transaction results carrying `status:"REJECTED"` and a stable `failureCode` | the user confirmed the contract distinction between correctable requests and auditable definitive outcomes | active | 2026-09-18 |
| AD-022 | `POST /wagering/transactions` returns `200` for durable processed/rejected/replay results, `202` for `PENDING_REFERENCE`, `422` for invalid commands with no record, and `503` before a durable commit | the user confirmed business outcomes are transport-successful and pending acceptance is distinguishable | active | 2026-09-18 |
| AD-023 | The provided HTTP routes are implicit v1; an incompatible contract change requires a new route or media type | the user confirmed literal route preservation while allowing explicit future evolution | active | 2026-09-18 |
| AD-024 | HTTP request bodies are capped at 1 MiB; server read-header/read/write/idle timeouts are 5/10/35/60 seconds; reconciliation has a 30-second deadline; and each instance admits at most 256 concurrent business requests, rejecting the next with `503` and `Retry-After: 1` | the user confirmed concrete per-instance resource limits without inventing a distributed provider quota | active | 2026-09-18 |
| AD-025 | Ledger pages are ordered ascending by `(createdAt,id)`, use an opaque versioned base64url cursor, and expose `limit` with default 50 and bounds 1 through 100 | the user confirmed keyset pagination that remains stable while new ledger entries are appended concurrently | active | 2026-09-18 |
| AD-026 | The SQS ingress uses 20-second long polling, batches of up to 10, a 60-second visibility timeout renewed every 20 seconds, redrive after 5 receives, and transient visibility backoff of 5/10/20/40 seconds by receive count | the user confirmed bounded polling and redelivery behavior that supports safe shutdown and moves the fifth receive to the DLQ | active | 2026-09-18 |
| AD-027 | Each SQS provider uses a distinct IAM user or role; the consumer requests `SenderId`, maps it to a configured provider, and requires equality with `data.providerId`; Compose provisions distinct LocalStack identities | the user confirmed that a shared queue cannot authorize providers from the untrusted body alone and that the broker identity must be the provider authority | active | 2026-09-18 |
| AD-028 | The ingress FIFO message uses `MessageGroupId=walletId` and `MessageDeduplicationId=messageId` | the user confirmed per-wallet ordering without blocking independent wallets, while keeping PostgreSQL as the financial authority | active | 2026-09-18 |
| AD-029 | Outbound events are published to FIFO queue `wager-events.fifo` with `MessageGroupId=walletId` and `MessageDeduplicationId=eventId` | provides a durable destination with aggregate-level ordering and stable identity during republishing | active | 2026-09-18 |
| AD-030 | Outbox publication uses batches of 50, a 30-second lease, backoff from 1 second to 5 minutes, and unlimited retries while unpublished | an event committed to the database cannot be lost due to exhausted retries | active | 2026-09-18 |
| AD-031 | The reference worker claims up to 50 pending references per 30-second lease using `SKIP LOCKED` | enables multiple instances and recovery of abandoned work | active | 2026-09-18 |
| AD-032 | All events start at `version: 1`; timestamps are UTC RFC 3339 with milliseconds; optional fields are omitted, not sent as `null` | fixes a consumable and consistent contract | active | 2026-09-18 |
| AD-033 | Transactions, ledger, reversal claims, and idempotency do not expire; inbox and outbox are not purged in this challenge; DLQ has 14-day retention | prevents old replays from reapplying money and avoids inventing a retention policy | active | 2026-09-18 |
| AD-034 | Reconciliation uses `REPEATABLE READ`, reads the full ledger, performs no write locks; 30-second timeout returns `503` without partial results | produces a consistent view without blocking movements during a full scan | active | 2026-09-18 |
| AD-035 | Logging via `slog` in JSON format with Prometheus on `GET /metrics`; fixed metric names `wager_transactions_total`, `wager_idempotency_duplicates_total`, `wager_retries_total`, `wager_dlq_total`, `wallet_concurrency_conflicts_total`, `outbox_oldest_pending_seconds`, `wager_processing_duration_seconds`, `wallet_reconciliation_divergences_total`; no tracing | uses standard library for logging, fixes low-cardinality labels, and delivers mandatory signals | active | 2026-09-18 |
| AD-036 | Integration tests run on real subprocesses with failpoints enabled only in integration build binaries; production configuration rejects failpoints at startup | makes reproducible the time windows between commit, delete, publish, and acknowledgment | active | 2026-09-18 |
| AD-037 | The layout is `cmd/` for entry points, `internal/{domain,application,adapters,integration}` for all service code, and root `migrations/`; no `pkg/` | the service is an application, not a library, so `internal/` prevents accidental external imports while keeping the approved dependency direction | active | 2026-09-18 |
